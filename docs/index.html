01 What's in the box

Two Krita plugins and three command-line tools. The plugins use only Krita's bundled Python (PyQt5 + stdlib), so there is nothing to pip-install inside Krita.

Drive a live Krita

Drop a JSON file into a folder and Krita picks it up within 500 ms. It can insert an image, export the canvas or open a project. Results come back in done/ or as an .error.json. It uses no sockets and runs no server.

Layered files from code

kra_prepare turns plain PNGs into raw BGRA tiles and a manifest. kra_build then runs inside headless kritarunner and writes a real .kra with one group per object, already set up for clipping-mask painting.

02 The clipping-mask move

Every object kra_build makes follows the same pattern. You paint on the top layer, and it can never spill off the shape underneath.

  • Inherit Alpha = clipping mask. The layer only shows where the layers below it in the same group already have pixels.
  • Normal covers, Color tints. Use Multiply for shadows and Add for highlights, each on its own Inherit-Alpha layer.
  • White paints grey? The brush is textured or Flow is under 100%. Switch to a hard round at Flow 100, or use Edit ▸ Fill with Foreground Color.
  • Golden rule for agents: never edit the artist's live file. Render to new files and wait for sign-off.

03 Talk to Krita from a shell

krita_bridge.py queues a command, waits for Krita to answer, and exits 0 on success, 1 on failure or 2 on timeout. A script or AI agent never has to watch folders itself.

MS-DOS Prompt — krita_bridge_□×
$ python3 tools/krita_bridge.py ping
{ "action": "ping", "status": "succeeded",
  "message": "pong (protocol 2, Krita 5.2.6, active: mycard.kra)" }

$ python3 tools/krita_bridge.py insert result.png --name "AI result" --scale 0.5
# → new paint layer in the active document, red stays red (BGRA-correct)

$ python3 tools/krita_bridge.py export --max-side 1024
# → ~/.krita-image-uploader/krita/latest.png + latest.json

$ python3 tools/krita_bridge.py live on   # stream the canvas every 2 s
